iOS, Flutter, React Native 앱을 구조화하는 방법에 관한 링크 모음입니다. 먼저 공식 지침을, 그다음 이를 실제로 적용하는 라이브러리, 샘플 앱, 도구를 소개합니다. 모든 항목은 사람이 직접 열어 읽었고, 그 링크에서 무엇을 얻을 수 있는지 한 줄로 설명합니다. 매주 실행되는 작업이 보관 처리되었거나 이름이 바뀌었거나 540일 동안 업데이트되지 않은 저장소와 응답하지 않는 링크를 표시하므로, 목록이 모르는 사이에 낡아 가지 않습니다.

## 주요 기능

- **세 가지 플랫폼, 하나의 구조** — iOS, Flutter, React Native 섹션이 같은 카테고리로 구성되어 있으며, 패턴의 출처가 되는 플랫폼 독립적인 글도 함께 실었습니다.
- **모든 링크에 이유가 있습니다** — 각 항목에 한 줄짜리 "왜"가 있으며, "최고"와 같은 마케팅성 표현은 검사기가 거부합니다.
- **모으기만 하지 않고 확인합니다** — 항목은 [data/entries.json](data/entries.json)에 있으며, push할 때마다 검증되어 이 README에 반영됩니다. GitHub 활동과 링크 상태는 매주 확인합니다([방법](docs/guides/keeping-the-list-current.md)).
- **같은 기능을 세 가지 스택으로** — SwiftUI, Flutter, React Native로 만든 [독서 목록 예제](Examples/README.md)이며, 43개의 테스트가 각 플랫폼에서 같은 규칙을 검사합니다.
- **최신 플랫폼 변경 사항** — 네이티브, Flutter, React Native 앱에 요구되는 iOS 27 scene 수명 주기에 관한 [가이드](docs/guides/ios-27-scene-life-cycle.md)입니다.

```sh
git clone https://github.com/muhittincamdali/awesome-mobile-architecture.git
cd awesome-mobile-architecture/Examples/flutter/reading_list   # or ios/ReadingList, react-native/reading-list
flutter test                                                  # swift test, or npm ci && npm test
```

**3. 구조가 얼마나 필요한지 정하세요.** [아키텍처 선택하기](docs/guides/choosing-an-architecture.md)는 세 플랫폼에 공통된 개념을 정리하고, TCA, Bloc, Redux Toolkit 같은 라이브러리가 언제부터 효과를 내기 시작하는지 알려 줍니다.

## 어디서나 통하는 개념

### 공식 지침

- [Guide to app architecture (Android)](https://developer.android.com/topic/architecture) - UI 계층, 데이터 계층, 단방향 데이터 흐름에 대한 Google의 가이드입니다. 같은 구분이 iOS, Flutter, React Native에서도 쓰입니다.
- [Presentation Model](https://martinfowler.com/eaaDev/PresentationModel.html) - MVVM의 기원이 된 패턴으로, 뷰의 상태와 동작을 UI 없이 테스트할 수 있는 클래스에 담습니다.
- [The Clean Architecture](https://blog.cleancoder.com/uncle-bob/2012/08/13/the-clean-architecture.html) - 계층 간 의존성 규칙을 다룬 원문으로, 대부분의 모바일 클린 아키텍처 템플릿이 이 글을 바탕으로 합니다.
- [The Elm Architecture](https://guide.elm-lang.org/architecture/) - Model, update, view: TCA, Redux, BLoC의 바탕이 된 단방향 루프를 짧은 몇 페이지로 설명합니다.

## iOS

### 공식 지침

- [Discover Observation in SwiftUI](https://developer.apple.com/videos/play/wwdc2023/10149/) - Observation이 뷰가 읽는 프로퍼티를 추적하는 방식을 다룬 WWDC23 세션으로, 현재 SwiftUI 뷰 모델의 기반입니다.
- [Managing model data in your app](https://developer.apple.com/documentation/swiftui/managing-model-data-in-your-app) - `@Observable` 모델과 `@State`, `@Environment`, `@Bindable`로 누가 소유하는지에 대한 Apple의 단계별 설명입니다.
- [Migrating to the Observable macro](https://developer.apple.com/documentation/swiftui/migrating-from-the-observable-object-protocol-to-the-observable-macro) - `ObservableObject` 뷰 모델을 `@Observable`로 옮기는 정확한 수정 내용과 뷰 업데이트 방식의 변화를 보여 줍니다.
- [Swift 6 migration guide](https://www.swift.org/migration/documentation/migrationguide/) - 데이터 경쟁 안전성, `Sendable`, actor 격리를 단계별로 설명합니다. 모든 Swift 6 아키텍처가 따라야 하는 규칙입니다.
- [TN3187 UIKit scene-based life cycle](https://developer.apple.com/documentation/technotes/tn3187-migrating-to-the-uikit-scene-based-life-cycle) - app delegate만 쓰는 앱을 `UIScene`으로 옮기기 위한 Apple의 기술 노트로, iOS 27 SDK로 빌드하는 앱은 반드시 적용해야 합니다.

### 상태 및 아키텍처 라이브러리

- [Swift Async Algorithms](https://github.com/apple/swift-async-algorithms) - Debounce, throttle, merge 등 뷰 모델에서 Combine 파이프라인을 대체하는 `AsyncSequence` 연산자입니다.
- [Swift Sharing](https://github.com/pointfreeco/swift-sharing) - 프로퍼티 래퍼 하나로 기능 간에 상태(user defaults, 파일, 메모리)를 공유하고 유지합니다.
- [The Composable Architecture](https://github.com/pointfreeco/swift-composable-architecture) - reducer, effect, 의존성을 하나의 라이브러리로 제공하며, 모든 상태 변화를 검증하는 테스트 store가 있습니다.
- [Workflow (Swift)](https://github.com/square/workflow-swift) - UI를 렌더링하는 Square의 조합 가능한 상태 머신으로, Android 앱용 Kotlin 라이브러리도 짝으로 있습니다.

### 의존성 주입

- [Factory](https://github.com/hmlongco/Factory) - 컴파일 시점에 검사되는 등록과 테스트별 재정의를 갖춘 컨테이너 기반 주입으로, 코드 생성이 필요 없습니다.
- [Needle](https://github.com/uber/needle) - 코드에서 생성되는 Uber의 컴파일 시점 검사 의존성 그래프로, 모듈이 많은 앱을 위해 만들어졌습니다.
- [Swift Dependencies](https://github.com/pointfreeco/swift-dependencies) - 뷰 밖에서도 동작하며 테스트마다 테스트용 값으로 바꿔 끼울 수 있는 environment 방식의 의존성 주입입니다.
- [Swinject](https://github.com/Swinject/Swinject) - 객체 스코프를 지원하는 런타임 컨테이너로, 시작 시점에 의존성을 해석하는 UIKit 코드베이스에서 흔히 쓰입니다.

### 내비게이션

- [Swift Navigation](https://github.com/pointfreeco/swift-navigation) - SwiftUI, UIKit, AppKit을 위한 상태 기반 내비게이션으로, 이동 대상은 모델의 optional 또는 enum case입니다.
- [XCoordinator](https://github.com/QuickBirdEng/XCoordinator) - 타입이 지정된 라우트를 쓰는 UIKit용 Coordinator 패턴으로, 뷰 컨트롤러가 서로 push하지 않게 됩니다.

### 샘플 앱

- [Clean Architecture for SwiftUI](https://github.com/nalexn/clean-architecture-swiftui) - SwiftData 영속성, 네트워킹, 의존성 주입, 단위 테스트가 각각 별도 계층에 있는 SwiftUI 앱입니다.
- [iOS Clean Architecture MVVM](https://github.com/kudoleh/iOS-Clean-Architecture-MVVM) - DI 컨테이너, 플로 coordinator, DTO 매핑, 계층 전반의 응답 캐싱을 갖춘 UIKit 템플릿입니다.
- [TCA example apps](https://github.com/pointfreeco/swift-composable-architecture/tree/main/Examples) - 사례 연구와 Todos, Voice Memos, SyncUps, Search 앱이 있으며, 라이브러리 릴리스에 맞춰 갱신됩니다.

### 테스트

- [SnapshotTesting](https://github.com/pointfreeco/swift-snapshot-testing) - 뷰와 값을 참조 파일로 기록하고 변경되면 실패하게 하여, 단위 테스트가 놓치는 UI 회귀를 잡아냅니다.

### 프로젝트 구조와 도구

- [Tuist](https://github.com/tuist/tuist) - Swift 매니페스트로 Xcode 프로젝트를 생성하여, 앱이 커져도 모듈 경계를 분명하게 유지합니다.

- [Riverpod](https://github.com/rrousselGit/riverpod) - 비동기 상태, 캐싱, 의존성 주입을 위한 컴파일 시점에 안전한 provider로, 위젯 트리 없이 테스트할 수 있습니다.
- [Signals.dart](https://github.com/rodydavis/signals.dart) - Dart와 Flutter를 위한 세밀한 반응형 signal로, 바뀐 값을 읽는 위젯만 다시 빌드합니다.

- [Very Good CLI](https://github.com/VeryGoodOpenSource/very_good_cli) - 계층형 구조, 테스트, 엄격한 lint가 이미 설정된 앱과 패키지를 만듭니다.

## React Native

### 공식 지침

- [About the New Architecture](https://reactnative.dev/architecture/landing-page) - Fabric, TurboModules, JSI를 설명하며, 0.76부터 새 React Native 앱이 기본으로 사용하는 아키텍처입니다.
- [Managing State (React)](https://react.dev/learn/managing-state) - 상태를 구성하고, 끌어올리고, reducer와 context로 옮기는 방법을 다룬 React의 공식 가이드입니다.
- [Testing overview](https://reactnative.dev/docs/testing-overview) - 단위, 컴포넌트, 엔드투엔드 테스트의 공식 안내도와 각각이 앱의 어느 계층을 다루는지 설명합니다.

### 상태 및 아키텍처 라이브러리

- [Jotai](https://github.com/pmndrs/jotai) - 원자적 상태: 하나의 전역 store 대신 작은 atom을 조합하며, 계산된 값에는 파생 atom을 씁니다.
- [Legend-State](https://github.com/LegendApp/legend-state) - 영속성이 내장된 세밀한 반응형 상태로, 데이터를 기기에 보관하는 앱에 알맞습니다.
- [MobX](https://github.com/mobxjs/mobx) - 의존성을 자동으로 추적하는 observable 상태로, 컴포넌트는 읽은 값이 바뀔 때만 다시 렌더링됩니다.
- [Redux Toolkit](https://github.com/reduxjs/redux-toolkit) - Redux를 작성하는 공식 방법으로, slice, 변경하듯 쓰는 불변 업데이트, 서버 데이터를 위한 RTK Query를 제공합니다.
- [TanStack Query](https://github.com/TanStack/query) - 서버 데이터를 UI 상태와 분리해 자체 계층에 두고, 캐싱, 재요청, 재시도를 제공합니다.
- [XState](https://github.com/statelyai/xstate) - 결제나 온보딩처럼 상태와 전환이 많은 흐름을 위한 상태 머신과 statechart입니다.
- [Zustand](https://github.com/pmndrs/zustand) - provider가 필요 없는 작은 hook 기반 store로, selector가 다시 렌더링을 바뀐 부분으로만 제한합니다.

### 내비게이션

- [Expo Router](https://docs.expo.dev/router/introduction/) - Expo와 React Native 앱을 위한 파일 기반 라우팅으로, 모든 화면에 URL이 생기고 딥 링크가 동작합니다.
- [React Navigation](https://github.com/react-navigation/react-navigation) - React Native용 stack, tab, drawer navigator이며, Expo Router가 이 위에 만들어져 있습니다.

### 샘플 앱

- [Obytes React Native template](https://github.com/obytes/react-native-template-obytes) - Expo Router, React Query, 폼 처리, CI가 이미 연결된 Expo 및 TypeScript 스타터입니다.

## 항목 선정 기준

항목은 앱 구조를 잡는 데 도움이 되고 사람이 읽어 본 경우에 추가하며, 인기가 있다고 해서 추가하지 않습니다. 다음 조건이 필요합니다.

- 공식 출처이거나, 동작하는 코드로 패턴을 보여 주는 라이브러리, 샘플 또는 글일 것
- GitHub 저장소의 경우: 보관 처리되지 않았고 최근 540일 이내에 push가 있을 것
- 독자가 무엇을 얻는지 쉬운 말로 설명하는 한 줄짜리 이유가 있을 것

나중에 이 규칙을 충족하지 못하게 된 항목은 제거하거나 교체합니다. 알려진 범위 밖: Android 전용 자료와 Kotlin Multiplatform 자료는 다루지 않으며, 유료 강의는 싣지 않습니다.
